# State-transfer building blocks

Use these operator helpers for Ingenium state preservation. They do not control services or deploy workloads. Keep every generated manifest, archive, temporary restore and receipt under the current task's one declared output root. Measure Windows C: and destination headroom before large stages; account for temporary plaintext SQLite snapshots plus ciphertext under the existing20GiB C:/WSL task ceiling.

## Scope and source fence

Discover current container mounts, original model/bootstrap native Secret fingerprints and active file writers. Preserve all required state, original local installation and rollback sources. A configured project lives under the core store unless its actual workspace metadata says otherwise. For the authorized external workspace, retain source, uncommitted files, Git metadata/path aliases and required related worktrees. Record exact excluded generated directories; leave those originals and unique test evidence on the PC. A Docker image download is a separate size.

Stop the original Ingenium writer only in the controlled cutover after a healthy redundant target claim and recovery plan exist. Verify no source container/writer still uses its application volumes. Do not stop unrelated host processes. The separately mounted readonly host OpenCode history may have its own active writer: use `legacy_history_snapshot.snapshot(source_db, target_db)` through a readonly SQLite transaction. It verifies schema/table counts and quick_check, and preserves the original. Later host OpenCode writes stay on the original host; this does not migrate that separate service.

The full cold application snapshot must coordinate the core and container-owned native OpenCode stores plus configuration, attachments, skills, encrypted vault/authentication/backup keys, VS Code state and required workspaces. An independently consistent legacy-history snapshot does not prove that full cold interval or target acceptance.

## Manifest and archive

Run Python with `-B` to avoid bytecode outside the task root. `state_manifest.inventory(scope)` takes `sources`, each containing a physical `source` directory and logical `target` subdirectory. Optional `excludedPreservedOnSource` contains exact relative paths recorded during sizing. `overrides` maps selected relative paths to operator-owned stable snapshots; `omittedSupersededFiles` omits only files replaced by an independently verified equivalent, such as SQLite WAL/SHM when its coherent DB snapshot is supplied. Do not omit application records or unreadable files to fit storage.

Inventory hashes every regular file with no-follow identity/change checks, records numeric ownership, modes, nanosecond timestamps, ACL/xattrs, hardlinks and literal symlinks, and refuses special entries. The current reviewed bound is350,000 entries/12GiB apparent file data. A larger installation needs explicit review of storage and bounds, not silent truncation. `sourceFenceVerified:false` deliberately remains in the manifest: the caller must bind actual external quiescence evidence separately.

`encrypt_archive(manifest, destination, recipient_file)` streams GNU tar with ACL/xattrs and numeric owners through gzip/age. Symlink values remain unchanged; archive/hardlink names map to logical state subdirectories. It uses the existing SHA-bound age binary and existing recipient, refuses output replacement and bounds ciphertext. Retain any failed partial ciphertext for review. There is no plaintext full-tar stage.

`verify_archive(manifest, archive, identity_file)` checks the complete expected member set, types, owners/modes, file hashes and link targets, then drains decrypted EOF and requires successful age authentication. Encrypt the private manifest separately and verify its authenticated readback; do not put paths/hashes or credentials in Git. Hash large archives through an open stream, never an archive-sized read.

## Independent restoration and cutover

After archive authentication, independently extract into an empty task-owned restore directory or the exact intended retained target claim using numeric owners, ACLs/xattrs, same permissions and delayed directory restoration. Require success from both decrypt and extraction, draining age output to EOF. Do not launch the app entrypoint during restore.

Construct target scope using the same logical targets, run inventory again, and call `assert_same(expected, actual)` for exact contents/metadata/path set. Verify each SQLite database independently and compare original data/account fingerprints. Confirm target volume identities, two healthy replicas and actual remaining filesystem/PVC capacity. A local fixture or local history-only restore is preparation, not the cluster's complete application restoration.

For files taken from a stopped container's writable layer, verify numeric ownership against the source archive headers before accepting local staging. On this installation, Docker CLI local extraction normalized those home files to root ownership despite `--archive`; comparing a target against that incorrect staging alone cannot establish source metadata preservation. Prefer streaming the source archive through GNU tar with explicit numeric/same-owner extraction and verify every header. Docker archive timestamps may have only second precision; preserve the original container and record that limitation. The bounded `repair_container_home_metadata.py` accepts authenticated operator-held source metadata on stdin, checks existing file hashes and allowed home paths, and corrects only owners/modes. If a correction is needed after a cold capture, encrypt and independently back up its metadata alongside that capture and apply it after restoration. Never overwrite changed live file content to repair permissions.

After real source quiescence and full target readback, publish the reviewed one-writer chart through the existing local CI/validated/Flux pipeline. Verify app behavior and Pod replacement before completion. For cleanup, retain authenticated encrypted recovery archives, minimal receipts and original data. Remove temporary plaintext snapshots/independent-restore trees only after exact target containment, no active reference/mount, surviving original/verified ciphertext and a known regeneration procedure are confirmed. Report measured Linux recovery separately from Windows free space.

## Container aliases and legacy component scope

Use `writer_audit.audit(scope, source_container_id)` for the actual cold-input scope. It indexes source file identities and checks writable descriptors plus shared writable mappings across processes; pathname-prefix checks miss writes through container aliases. Inspect inventory/permission failures rather than treating missing observations as no writer. Bind this observation to actual stopped Docker/container identity and repeat it around capture. Readonly host processes are not automatically source application writers.

When code, live process paths and consumed configs establish that the separate host OpenCode mount contributes only its legacy fallback database, transfer the complete coherent DB instead of its unrelated host MCP installs/logs/Git snapshots. Preserve every original host file; native container OpenCode state still transfers in full. Keep the database's original numeric metadata and the original legacy root directory metadata. Restore the verified encrypted history component first, then the cold component containing the legacy root's proper metadata. `merge_expected_manifests([history, cold], {'host-opencode'})` permits only that reviewed duplicate directory, never duplicate files. It produces independent-restore expectations, not a new capture plan. Build target inventory scope without source exclusions so unexpected target files cannot be silently ignored.
