# Agent instruction authoring

## Auto-approve and autonomous work

For Build auto/no-question work, read [the autonomy contract](../development-conventions/references/autonomous-work.md).
Reuse exact authority, use reversible defaults or record blockers without routine
questions. Native permissions, mode limits and separate consequential gates remain.
Delegation off/unknown stays off. This skill does not authorize implementation,
goal creation/resumption, configuration changes, deployment or publication.

## Workflow

1. Inspect the consumer's applicable parent/nested instructions, actual loader,
   configuration, current dirty source and owners. Identify how instruction files
   combine; do not assume a universal closest-file override or provider behavior.
2. Inventory every mandatory rule, rationale and user requirement before shortening.
   Map each to retained visible text, one owning procedure, verified completed
   evidence, explicit later user supersession or a concrete blocker. Do not lose
   work through summarization or interpret cancelled goals as finished outcomes.
3. Keep critical approval/privacy/mode/dirty-work and parent-goal boundaries
   visible. Route recognizable tasks to specific skills and policy owners, with
   “read when” triggers. Links do not load bodies or references automatically.
4. Separate portable procedures from the consumer's paths, branding, commands,
   limits, historical evidence and operational state. Use the consumer's existing
   catalogs/docs; avoid competing policy copies or bulk moves without need.
5. Define selective memory retrieval only if requested: exact scope, task query,
   result/read budget, no-match/unavailable fallback, stale/poisoned evidence and
   no implicit writes or lifecycle authority. Instruction-guided retrieval is not
   deterministic injection; do not quietly add a runtime hook.
6. For research or architecture evaluation, explicitly read
   [research and evaluation](references/research-and-evaluation.md). Compare
   keeping current instructions, an index with visible safeguards, links-only,
   and narrowly scoped nested rules; do not treat a line target as a scientific law.
7. Present substantive design, policy migration, tradeoffs and acceptance before
   implementation when required. Only with actual authority edit canonical source;
   use `skill-maintenance` for packaging/catalog validation, not as another policy owner.
8. Verify paths/anchors/schema/coverage and distinct failure regressions; then
   distinguish source checks from fresh model routing, runtime loading and user
   outcomes. Report missed rules, irrelevant reads, tokens/latency and uncertainty.

## Verification and audit trail

Parent alone manages goals and accepts evidence; do not delegate goal planning.
Preserve earlier decisions, reasons, actions, checks and blockers in the consumer's
repo-local archive convention, without raw goal edits or private transcript dumps.
Missing/superseded work needs an explicit disposition, not silent disappearance.
Validate archive ownership/checksum semantics and selected live revision separately;
integrity alone is not freshness. Never overwrite uncertain existing work to pass.

For usage examples, read [README.md](README.md). It and supporting references
are not loaded automatically. This skill has no universal line ceiling, source
directory, required tool, runtime hook or deployment mechanism for consumers.
