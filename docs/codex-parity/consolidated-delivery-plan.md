## Outcome and operating decisions

Deliver the full scope in [request coverage](../request-coverage.md): all 68
requirements and F01–F07, including inherited coordination, screenshot, window,
memory, import, handoff, model-efficiency, PR and demo work. Do not replace that
scope with “the source tests passed” or a smaller documentation-only objective.

1. Keep one parent-owned execution queue in this chat and one writer per exact
   path. Children implement bounded units; they never own goal planning.
2. Treat technical unknowns as implementation or investigation tasks. An unresolved
   lane does not stop unrelated lanes or trigger repeated approval questionnaires.
3. Reuse existing exact authority. Keep the current native/consequential safety
   rules; do not make a new substantive authorization policy a prerequisite for
   source delivery or ask the user to choose an unnecessary policy package.
4. Prefer isolated fixtures, disposable profiles and scratch instances over
   modifying the user's running service merely to test a feature.
5. Keep an evidence ladder: source, installed bytes, loaded runtime, actual model
   behavior, visible outcome. Never promote one layer to another.
6. Preserve every unrelated dirty/staged/untracked byte, original media and the
   staged `resume.md` to `handoff_resume.md` rename. Preserve uncertainty rather
   than inventing provenance or retroactive preservation evidence.
