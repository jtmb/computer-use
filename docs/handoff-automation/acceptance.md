## Supported surfaces and limitations

Inspected the official V2 [server plugin](https://opencode.ai/v2/docs/build/plugins/server),
[TUI plugin](https://opencode.ai/v2/docs/build/plugins/cli),
[RPC](https://opencode.ai/v2/docs/build/plugins/rpc) and
[API](https://opencode.ai/v2/docs/api) guides, plus the installed published
`@opencode/plugin`, `@opencode/client` and `@opencode/schema` 2.1.1 declarations.

- `session.hook("context")` requests a source-authored handoff in a model's next
  normal context; `title` preserves worker identity. No invented lifecycle event,
  background scheduler, recursive prompt or legacy goal-transfer RPC is used.
- The `compaction` hook controls a summary request/result, not a documented
  pre-compaction cancellation boundary. No compaction hook is registered in
  either mode. Native/provider compaction can occur first or below 500k.
- Current-context usage is the latest completed assistant step after completed
  compaction, not session lifetime totals. The implementation follows the
  installed client `lastAssistantWithUsage` selection boundary conservatively
  (unknown latest usage stays unknown) and schema `TokenUsage.total` arithmetic.
  It is an estimate; new system/tool material is not prospectively counted.
- No native TUI Open settings-page extension was found. **Ctrl+P → Handoff
  settings** is a supported, separately labeled palette command and selector.
  It uses server plugin storage and a separate settings RPC, not `cli.json` edits,
  a new native setting, deployment, or a security grant. Same-user authenticated
  RPC access is not human-only provenance.
- Requests are at most once per source session in the owning plugin instance,
  durably latched before exposure. Ordinary restart reads the latch; unload
  cancellation prevents old-generation exposure. Native storage has no exposed
  compare-and-swap transaction, so this is not a claim about independently
  misconfigured concurrent servers sharing storage. Settings are revision-checked
  and serialized with triggers. OFF does not recall an already-issued request.
- Missing/malformed state, unknown ownership or an uncertain write fails closed.
  A crash after saving but before exposing the request may lose that automatic
  request. Manual `/handoff` is the reconciliation path; no automatic retry or
  goal/status/limit/approval migration is attempted. Native goal auto-continuation
  is not stopped by this request; the source model and receiver still need live
  source/worker overlap checks. This is not an exactly-once transfer engine.
